## 记一单，还得等颜料？

早上，奶茶店刚开门，店员就在柜台的电脑上打开了一个记单小网页。

这个页面很简单：上面写着“今日订单数：0”，下面有个“记一单”按钮。店员每接到一单，就点一下，数字应该跟着加一。页面角落还有个“查看统计”，忙完了可以点开，看看今天的订单统计图。

第一位客人点好了奶茶。店员伸手点了一下“记一单”，等着那个零变成一。

没动。

又点一下。

还是零。

屏幕里面，浏览器老大拎着第三次点击冲进执行大厅：“按钮都摆出来了，谁负责接？”

JavaScript 老大正站在门口，手里捏着一张开工单。

“我还没给按钮安排工作。”

“那就安排啊！”

“人没齐。”

记账员抱着账本，坐在旁边。负责把数字写到屏幕上的面板员，也到了。

浏览器老大挨个点过去：“一个记，一个写，还缺谁？”

JavaScript 老大指向远处。

统计员拉着图表员，图表员伸长脖子，等一只推着颜料箱的小家伙。

“配色的还在路上。”

浏览器老大看向页面角落。那里有个“查看统计”按钮，从开门到现在，一次也没被点过。

“没人看图。现在只想记一单。”

JavaScript 老大也觉得不对，拎起门口的 `import`。

“我只是让你把统计员请来，怎么连颜料都订上了？”

`import` 递出一叠申请单。

“统计员说，画图得找图表员。图表员说，颜色得找配色员。”

“那记账为什么也不开工？”

`import` 指着最上面那张单子。

那张单子，是 JavaScript 老大自己签的。

## 单子上到底写了什么？

记单页面原本只有一个大文件。

记账、改屏幕上的数字、画统计图，挤在一起。前几天只想换个图表颜色，开发者却在长长的代码里找了半天。

于是，几份工作被拆开了。

`counter.js` 保管当天的订单数；`panel.js` 负责显示数字；`report.js` 负责统计图。文件名后面的 `.js`，表示里面装着 JavaScript 代码。

还有一份 `main.js`，留在入口处负责调度：哪个按钮被点了，就叫谁做事。

加载员给这些文件各安排一间房。

“这次按模块管理。各自房里的名字归各自管，想用别人的东西，要走窗口。”

记账员挂出第一份工作说明：

```javascript
// counter.js
export let count = 0;

export function increment() {
    count += 1;
}
```

浏览器老大盯着那几个英文。

“翻译一下。”

“`count` 是账本上的订单数，先记零。”记账员把零写在纸上，“`increment` 是一项动作：叫我一次，我就在原来的数字上加一。”

“前面的 `export` 呢？”

记账员把账本和“加一”按钮推到窗口边。

“这两个名字允许其他模块来用。”

加载员接着摊开入口的申请单：

```javascript
// main.js
import { increment } from "./counter.js";
```

“这句就是：到旁边的 `counter.js`，接上叫作 `increment` 的那项工作。”

“接上了，订单数就加一？”

“还没有。只是找到了按钮。等执行 `increment()`，才是真的按下去。”

JavaScript 老大试着隔着墙喊了一声 `count`。

没人答应。

入口这里只导入了 `increment`，没有导入 `count`。即使两个文件放在同一个文件夹里，也不会自动共享所有名字。

面板员也想读订单数，于是在自己的文件里另写了一行：

```javascript
// panel.js
import { count } from "./counter.js";
```

窗口这才接通。

“所以拆文件时，不能光拿剪刀剪。”浏览器老大看着两张申请单，“剪完还得告诉别人，东西在哪儿，叫什么。”

加载员点点头：“自己的东西留在自己的作用域里，需要合作的部分，明确导出、明确导入。这样的文件，就是这里的模块。”

## 顺着线找，怎么越来越远？

入口完整的名单上，写着三项：

```javascript
// main.js，开工前的名单
import { increment } from "./counter.js";
import { renderCount } from "./panel.js";
import { showReport } from "./report.js";
```

`renderCount` 负责把订单数写到页面，`showReport` 负责打开统计图。

名单下面，才是“点击记一单，就加一并更新数字”的安排。

浏览器老大把纸往下拽：“那先做下面的，统计图以后再说。”

加载员没放手。

“这三行叫静态导入。是在开工前声明：这份代码要依赖谁。得先处理这份名单，才能执行下面的代码。”

JavaScript 老大拿起笔，把第三行挪到了文件最末尾。

“现在呢？”

“还是你的依赖。”

加载员把那一行重新圈了出来。

静态 `import` 不像一条走到哪儿才办到哪儿的普通指令。即使写在模块末尾，也要在模块正文执行前处理。想把它藏进按钮的处理函数里也不行，这种声明只能写在模块顶层，也就是函数和条件块外面。

浏览器老大重新翻起名单。

“就三份文件，怎么等到了颜料？”

加载员摆好刚取回的 `report.js`。里面还有两张申请：

- 找 `counter.js` 读订单数
- 找 `chart.js` 画图

刚取回的 `chart.js` 里，又写着要找 `palette.js` 取颜色。

浏览器先取到入口文件，读出导入地址，再去取那些文件；拿到新文件后，继续找里面的导入。原来藏在文件里的要求，就这样一层层露出来。

加载员把每份文件钉在白幕上，用线连起来：

```text
main.js（入口）
├─ counter.js（记账）
├─ panel.js（显示数字）
│  └─ counter.js（还是刚才那份）
└─ report.js（统计）
   ├─ counter.js（还是刚才那份）
   └─ chart.js（画图）
      └─ palette.js（颜色）
```

“这张图，就是模块之间的依赖关系，叫模块图。”

JavaScript 老大终于看见了那条长线：入口要统计，统计要画图，画图要颜色。

“所以我写下一个名字，后面可能跟来好几个？”

“要把这项工作准备好，光请名单上的第一个人不够。”

URL 抱着 `./chart.js` 的地址卡赶回来。

“这前面的点和斜杠，是从哪儿开始找？”

加载员指着发出申请的文件。

“从它自己的地址找。假如统计模块在 `https://shop.example/js/report.js`，里面的 `./chart.js` 就指向同一目录下的 `https://shop.example/js/chart.js`。”

URL 把完整地址贴上包裹。

文件名只是门牌，解析成地址，浏览器才知道去哪儿取文件。这里讨论的是浏览器直接加载这些模块的情况；如果项目先经过打包工具整理，浏览器收到的文件和依赖关系可能已经变了。

远处的颜料箱还在运输。

记账员举起账本：“我这边真能干了。”

加载员指了指最上方的入口：“但给按钮安排工作的那份代码，还没轮到执行。”

## 人到了，为什么还是不开工？

颜料箱终于进门。

JavaScript 老大伸手去拉开工铃，加载员还在核对两边的名字。

面板员申请 `count`，记账员的窗口上有 `count`。这一条，接通。

“人都到了，还查这个？”

加载员在废纸上把 `count` 改成了 `total`，盖住原来的申请单。

“假如写成这样呢？”

记账员摇头。窗口上只有 `count` 和 `increment`，没有 `total`。

“浏览器不会猜这两个词是不是一个意思。如果真的这样写，链接就会报错，入口的代码也不会开始执行。”

加载员拿开废纸，把正确的线接回去。

文件加载回来后，还要把导入的名字接到对应的导出上。这一步叫链接。文件找到了，不等于要用的东西也找对了。

JavaScript 老大这才开始按依赖关系执行代码。

记账员先把订单数设成零；需要这份数字的面板和统计模块，随后完成各自的准备；最后入口给两个按钮安排工作。

函数被准备好，不等于里面的工作也做了。`showReport` 已经可以被调用，统计图却还没画，因为没人点“查看统计”。

“下载、接线、开工，原来是三回事。”浏览器老大拨了拨刚接好的线。

加载员在名册上写下对应的术语：加载、链接、求值。最后那个听起来很费脑子的“求值”，在这里就是执行模块的代码。

这张图没有互相绕回去的依赖，也没有异步初始化的等待，依赖模块先执行，用它的模块随后执行。文件谁先下载完，不决定谁先开工。

页面外，店员终于点成功一次。

零变成了一。

浏览器老大松了口气，又忽然抬头：“刚才明明是三个地方都找记账员，怎么才来了一本账？”

## 不能一人发一本吗？

JavaScript 老大正准备让记账员再复印两本。

加载员压住复印机。

“入口、面板、统计，找的是同一个地址。这个页面里，这个 JavaScript 模块只登记一份，顶层代码不会因为多一次导入就重跑一次。”

记账员在上岗时盖了个章：

```javascript
console.log("新账本，订单数从零开始");
```

计数器模块第一次执行，盖一次。

入口、面板、统计，虽然有三张导入申请，章却只盖了这一次。

三个使用者接向同一份模块，订单数不会因为有人晚来导入，就被重新设成零。这里说的是当前页面环境里解析到同一个 URL 的模块；刷新成新页面后，会有新的一轮执行。

浏览器老大把复印纸收了起来。

“那面板看到的，是开户时那个零，还是现在的一？”

面板员趴到窗口前。

“一。”

“刚才导入的时候，不是零吗？”

加载员把窗口后面的线拉了出来。线的另一端，直接接着记账员的 `count`。

“导入没有把当时的数字抄一份带走。读这个名字时，读到的是那一端当前的值。这叫活绑定。”

为了看看窗口里的值会不会变，JavaScript 老大提前导入了 `count` 和 `increment`。等第一次点击处理完，再暂停下来做三步实验：

```javascript
console.log(count); // 现在是 1
increment();       // 再记一单
console.log(count); // 现在是 2
```

浏览器老大转身看向屏幕。

屏幕上还写着一。

“不是说活的吗？”

面板员敲了敲玻璃：“账本上的数变了，屏幕上的字还没重新写。”

活绑定让下次读取拿到新值，不会自动替应用刷新页面。

所以面板员的工作是：每次被叫到，重新读一次 `count`，再把读到的数字写上去。

```javascript
// panel.js
import { count } from "./counter.js";

export function renderCount() {
    document.querySelector("#count").textContent = count;
}
```

这里的 `#count`，是给页面上显示订单数的位置贴的标签。整句长代码做的事，就是找到那个位置，换掉里面的文字。

JavaScript 老大叫了一声 `renderCount()`。

屏幕终于变成二。

“以后按钮点一次，就先叫 `increment()`，再叫 `renderCount()`。”

面板员伸手想直接把导入的 `count` 改成三，窗口却把笔挡住了。

这个导入名字不能由面板员重新赋值。这里要改数字，得调用记账模块提供的 `increment()`。如果导出的东西是对象，则另当别论：导入名字不能被重新赋值，不代表对象里面的属性全被冻结。

记账员把笔收回账本旁。

“数归我记。读多少次都行，别各写各的。”

## 没点统计，就别来凑热闹

按钮能用了，浏览器老大却没走。

“刚才等颜料的时候，店员已经点了三次。明天网再慢一点，还得这么等？”

HTML 解析器举着扳手路过，顺手指了指入口牌：

```html
<script type="module" src="./main.js"></script>
```

`type="module"` 告诉浏览器，把入口当模块处理。

这块写在 HTML 里的入口牌没有加 `async`。浏览器加载模块时，HTML 解析器可以继续搭页面；等文档解析完、这份模块图准备好，模块代码才安排执行。

所以开头出现了那个尴尬场面：按钮已经显示出来，接收点击的代码还没执行。按钮看着完整，点了却没人办事。

JavaScript 老大盯着名单上的 `report.js`。

“记账要用计数器，也要有人更新屏幕。但统计图，确实不用现在就准备。”

加载员拿出另一种邀请单：

```javascript
import("./report.js")
```

“带括号了？”

“这叫动态导入。运行到这一句，才发起导入。可以放进点击按钮后执行的函数里。”

JavaScript 老大先划掉入口顶部那行静态导入：

```javascript
import { showReport } from "./report.js";
```

加载员沿图检查了一遍。剩下的启动模块，也没有谁还在静态导入统计模块。

然后，入口的工作单改成了这样。页面上，`#add` 是“记一单”按钮，`#report` 是“查看统计”按钮：

```javascript
// main.js
import { increment } from "./counter.js";
import { renderCount } from "./panel.js";

renderCount();

document.querySelector("#add").addEventListener("click", () => {
    increment();
    renderCount();
});

const reportButton = document.querySelector("#report");

reportButton.addEventListener("click", async () => {
    reportButton.disabled = true;
    reportButton.textContent = "统计图准备中…";

    try {
        const report = await import("./report.js");
        report.showReport();
        reportButton.textContent = "查看统计";
    } catch {
        reportButton.textContent = "统计图没打开，请稍后再试";
    } finally {
        reportButton.disabled = false;
    }
});
```

加载员没有逐个念符号，只把这份工作单从中间折开。

上半张：一开门就准备记账。点“记一单”，加一，然后重写屏幕数字。

下半张：有人点“查看统计”，才去请统计员。请人的时候，按钮显示“准备中”，暂时不接受重复点击。

`import()` 返回一份叫 Promise 的结果凭据，表示这件事还可能在进行中。`await` 让这次按钮处理先等结果，其他点击仍有机会被处理，并不是把整个浏览器按下暂停。

等统计模块连同依赖加载、链接、执行成功，`report` 就能用来访问它导出的东西。接着调用 `report.showReport()`，图才真正画出来。这个例子里的画图动作是同步完成的。

如果模块没能加载成功，页面就把“准备中”换成失败提示，而不是让店员对着一个没反应的按钮猜。

“等到需要时再请，等待也没凭空消失。”JavaScript 老大看着“准备中”几个字。

“对。只是把这笔等待，留给真正要看统计的人。记账不必陪着。”

浏览器老大把页面刷新，故意让颜料运输慢下来。

这次启动名单里，没有统计员，也就没有顺着统计员带来的图表员和配色员。

点“记一单”。

一。

再点。

二。

然后点“查看统计”。

角落的按钮显示“统计图准备中…”。长长的亲友团这才从远处走来。

店员没等，顺手又记了一单。

三。

颜料箱抵达后，统计员打开图表。账本已经是三，统计员读到的也是三。

浏览器老大指着数字：“总算没另外领一本从零开始的。”

“还是那份模块记录。”加载员把线接回原来的记账室，“后来用动态导入请人，也不会把已经执行过的同一模块重新开张。”

JavaScript 老大合上名册，又补了一句：“画图如果计算太久，照样会占住我的工作台。晚点加载，不等于换了个人替我算。”

统计员点点头，把颜料箱从门口挪开。

关店前，浏览器老大最后看了一眼那条通道。

记账员守着一本账，面板员每次重新读数，统计员在按钮被点到时才带队进场。

`import` 站在门边，把两张邀请单分开挂好。

一张写着：开门要用。

另一张写着：点到再来。

这回，奶茶不用等颜料了。
