# What in Browser：角色档案

本文档根据现有 23 篇文章整理，用于保持后续故事的角色职责、性格、道具和关系一致。

角色分为三类：

- **固定角色**：可以跨篇出场，职责和性格不能随意改变。
- **部门角色**：代表浏览器中的一段机制，可以按故事需要再次出现。
- **客串角色**：为某个例子临时拟人化，不默认成为长期班底。

抽象概念可以临时开口说话，但不等于必须为它建立一个永久角色。

## 固定角色

### 浏览器老大

- **首次出场**：[《凌晨三点的 URL》](/what-is-url) 中以“浏览器”出现，[《URL hash 的委屈》](/what-is-hash) 开始稳定使用“浏览器老大”。
- **职责**：统筹浏览器内各部门，创建和调度请求，制定工作规则，处理跨部门冲突，并对页面最终行为负责。
- **性格**：急性子、行动派，容易被新方案打动；偶尔先拍板再补规则，出了事故会亲自协调。
- **常用动作与道具**：下命令、开会、盖章、发通行证、拉架；办公室和控制面板属于其活动范围。
- **关系**：是 JavaScript 老大、HTTP、TCP、HTML 解析器和渲染工人的上级协调者，但不会代替各部门亲自完成所有机制。
- **避免冲突**：不要把浏览器老大写成 JavaScript 老大；浏览器可以调度 JavaScript，但不等于所有浏览器行为都由 JavaScript 完成。

### JavaScript 老大

- **首次出场**：[《凌晨三点的 URL》](/what-is-url) 提到浏览器与服务器各有一位 JavaScript；浏览器一侧在 [《你是什么垃圾？》](/js-variable) 后形成稳定设定。
- **职责**：在执行大厅运行页面 JavaScript，管理调用栈，领取任务和微任务，调用函数，并与变量大厅、DOM 和渲染流水线协作。
- **性格**：嘴上抱怨、手上不停；爱吐槽代码和人类，责任心强，好奇心也强，偶尔自信过头。
- **常用动作与道具**：咖啡、解释器、工作台、白幕、类型转换器、调用栈盘子；头发日渐稀疏。
- **活动场所**：执行大厅、事件大厅、变量大厅，也会跑去 DOM 工地和像素工地处理事故。
- **避免冲突**：JavaScript 老大代表页面主线程上的 JavaScript 执行者，不代表浏览器只有一个线程；网络、解析、布局和绘制都有各自岗位。

### URL

- **首次出场**：[《凌晨三点的 URL》](/what-is-url)。
- **职责**：携带方案、主机、端口、路径、查询参数等地址信息，在浏览器各部门之间传递请求线索，并以“取回资源的跑腿者”承担故事视角。
- **性格**：好奇、容易紧张，有时迷糊，但会主动追问一路发生了什么。
- **常用动作与道具**：身上有多个口袋，抱着域名牌、地址卡和资源包裹；出发时可能被 HTTP 麻醉，回来时常被冷水唤醒。
- **关系**：先找 DNS 问地址，再与 HTTP、TCP 等运输部门合作；`hash` 是挂在 URL 后面却不会随 HTTP 请求去服务器的伙伴。
- **避免冲突**：URL 是地址与请求线索的拟人化载体，不负责可靠传输、报文封装或同源判断。

### HTTP

- **首次出场**：[《凌晨三点的 URL》](/what-is-url)，在 [《HTTP 的手术室》](/what-is-http) 形成完整设定。
- **职责**：按照 HTTP 规则拆装请求和响应，处理请求行、状态行、头字段和消息体，并与 TCP 或 QUIC 运输层协作。
- **性格**：早高峰时急躁，平时爱喝咖啡；脑子灵活，喜欢提出协议优化，但偶尔嫌脏活麻烦。
- **造型与道具**：白大褂、手术室、麻醉针、手术刀、胶带、文件夹和咖啡。
- **关系**：与 TCP 是长期搭档兼损友；与服务器一侧的 HTTP 有同学或朋友关系。
- **避免冲突**：HTTP 负责消息语义与封装，不亲自保证底层可靠传输，也不负责 CORS 或 Cookie 的最终放行。

### TCP 老司机

- **首次出场**：[《TCP 部门来了个实习生》](/what-is-tcp)。
- **职责**：建立连接，可靠、有序地运输字节，处理确认、重传、流量控制和拥塞控制，并管理连接的建立与关闭。
- **性格**：稳重、要强、爱面子，对自己的可靠性很自豪；喜欢与 HTTP 互损，面对新对手也不会轻易服输。
- **造型与道具**：咖啡、工作台、计数器、扫描机、按钮和蓝色运输车；车库是其常用场景。
- **关系**：带着一名 TCP 实习生；与 HTTP 是老搭档；与 QUIC 是竞争者，也是可以互相认可的同行。
- **避免冲突**：TCP 提供一条有序字节流，不理解具体 HTTP 请求属于哪一条业务 Stream。

### TCP 实习生

- **首次出场**：[《TCP 部门来了个实习生》](/what-is-tcp)。
- **职责**：学习并协助 TCP 老司机完成握手、传输和关闭连接等工作。
- **性格**：认真、好奇、崇拜老司机，喜欢记笔记，也会适时拍彩虹屁。
- **常用道具**：笔记本、工作台和运输车副驾驶安全带。
- **避免冲突**：实习生是 TCP 部门的固定年轻角色，不要另造一名承担相同位置的 TCP 新人。

### HTML 解析器

- **首次出场**：[《HTTP 的手术室》](/what-is-http)，并在 [《HTML 解析器罢工了》](/html-parser) 形成完整设定。
- **职责**：读取 HTML，协调分词与建树，按解析规则构建 DOM，并处理容错与脚本阻塞。
- **性格**：工作认真、脾气火爆，最讨厌别人堵住施工轨道；遇到不合理流程会摔扳手或拿出罢工牌。
- **造型与道具**：黄色安全帽、哨子、扳手、工具带、DOM 工地和事故回放杆。
- **关系**：经常催 JavaScript 老大交工；与布局工人惺惺相惜，罢工牌可以外借。
- **避免冲突**：HTML 解析器只负责把文档变成 DOM，不负责计算最终样式、布局或绘制像素。

### QUIC

- **首次出场**：[《Cookie 的行李检查》](/cookie) 结尾留下名片，在 [《TCP 老司机遭遇新对手》](/http3) 正式出场。
- **职责**：在 UDP 提供的数据报能力之上建立安全、可靠的传输，提供多条独立 Stream、TLS 1.3 集成和连接迁移能力。
- **性格**：年轻、自信、反应快，喜欢用一句玩笑激怒 TCP 老司机；关键工作上仍然认真。
- **造型与道具**：银灰色身影、胸前带 `Q` 的夹克、银色新车、确认单、重传器、控制仪、加密钥匙和 Connection ID 号码牌。
- **关系**：为 HTTP/3 提供运输能力；与 TCP 老司机是对手兼同事。
- **避免冲突**：QUIC 不是 UDP。UDP 是它借用的底层通道，可靠性、Stream 和加密等能力由 QUIC 自己实现。

### Web Worker

- **首次出场**：[《主线程今天不接客》](/web-worker)。
- **职责**：在独立线程和 Worker 全局环境中承接页面交出的重计算，通过消息与主线程交换可克隆或可转移的数据。
- **性格**：年轻、能干、嘴快，入职第一天就想越权修改页面；被拦后仍喜欢为自己争取权限。
- **造型与道具**：毛线帽、保温杯、空白工作牌、独立计算分部和双向消息电话亭；事故演练时有戴“二号”毛线帽的替身。
- **关系**：与 JavaScript 老大分工，Worker 负责后台计算，JavaScript 老大负责接收结果并更新 DOM；Service Worker 是住在网络路口的亲戚。
- **避免冲突**：Web Worker 没有页面的 `window` 与 `document`，不能直接操作 DOM；它也不是 Service Worker，不负责拦截页面网络请求或离线缓存。

### Service Worker

- **首次出场**：[《主线程今天不接客》](/web-worker) 结尾点亮网络岗亭，在 [《服务器不在，我替它回》](/service-worker) 正式出场。
- **职责**：注册在特定作用域内，按安装、等待和激活等生命周期工作；被浏览器唤醒后处理 `fetch` 等事件，并通过 Cache Storage 等能力为受控页面选择网络响应、缓存响应或降级响应。
- **性格**：自信、守规则但爱争权限，习惯把“拦车”称为“代理”；新版比旧版更急躁，遇到等待阶段会想强行上岗。
- **造型与道具**：长风衣、停车牌、网络路口岗亭、辖区地图、Cache Storage 仓库和版本工作牌。
- **关系**：是 Web Worker 的亲戚，与 HTTP 会围绕请求去向争执；注册、激活与客户端控制权由浏览器老大协调。
- **避免冲突**：Service Worker 不是常驻进程，不能依赖全局变量持久保存状态；没有 DOM 权限，不能绕过 HTTPS、CORS 或服务器业务校验，也不能把离线缓存写成无条件替代服务器。

## 部门角色

### JavaScript 与内存部门

| 角色 | 职责与性格 | 已有标志 | 使用提醒 |
| --- | --- | --- | --- |
| 全局对象 | 作为垃圾回收可达性检查中的根对象，负责沿引用关系点名；体型大、很骄傲 | 一包指针、老生区 | 是变量大厅里的长期角色 |
| 事件大厅小弟 | 登记任务，维护任务队列和微任务队列，把下一个任务交给 JavaScript 老大 | 登记台、任务号码牌 | 出场时用所在场景表明身份，后续直接称“小弟”即可 |
| 调用栈小弟 | 照看调用栈盘子、解释栈帧规则、提醒栈溢出 | 说明书、盘子和立柱 | 出场时写清正在照看调用栈，后续不用反复报岗位全称 |
| 内存清理员 | 根据可达性判断哪些对象和环境可以清理 | 清理小车、安全帽 | 不能因为函数返回就强行清理仍可达的词法环境 |
| 管房间的小弟 | 管理函数调用产生的词法环境，解释作用域链和闭包房间 | 房间门牌、钥匙和警报 | “钥匙”只表示函数与外部词法环境的联系 |

### DOM 与渲染部门

| 角色 | 职责与性格 | 已有标志 | 使用提醒 |
| --- | --- | --- | --- |
| 分词员 | 把 HTML 输入识别为 token | 剪刀、分词台 | 是 HTML 解析器团队成员，不是另一位总解析器 |
| 建树员 | 按 HTML 解析规则创建和插入 DOM 节点 | 起重机、节点槽 | 与分词员配合工作 |
| 预加载扫描员 | 在主解析器受阻时继续寻找可提前获取的资源 | 夜视镜、望远镜 | 只能提前发现和下载资源，不能越过阻塞脚本构建 DOM |
| 状态管理员 | 维护 `document.readyState` 等文档状态 | 可翻面的状态牌 | `interactive` 不等于所有延迟脚本都执行完成 |
| 样式管理员 | 根据 DOM 和 CSS 规则计算节点最终样式 | CSSOM 账本、衣服和色卡 | 后续写 CSS 层叠时应优先复用 |
| 布局工人 | 计算元素尺寸与位置，最恨 JavaScript 刚改完就追问 | 卷尺、方格图纸；卷尺曾弯成蚊香 | 布局不等于绘制，不要让其负责上色 |
| 绘制工人 | 把背景、文字、边框、阴影等画成绘制结果 | 刷子、油漆车 | 重绘不一定需要重新布局 |
| 合成员 | 管理画片与图层，把最终结果组合后送上屏幕 | 透明画片、轨道、合成控制台 | `transform`、`opacity` 可能主要经过合成，但不能保证永远只触发合成 |
| 场记员 | 在下一次绘制前接收 `requestAnimationFrame` 工作 | 场记板 | 不能保证回调不卡顿，也不能代替读写分离 |

### 网络、安全与存储部门

| 角色 | 职责与性格 | 已有标志 | 使用提醒 |
| --- | --- | --- | --- |
| DNS 递归解析器 | 接受完整域名问题，骑车依次查询并带回最终答案；严谨、容易对“踢皮球”不满 | 耳机、摩托车、印章、投诉表 | 与根、顶级域名和权威 DNS 的工作人员不是同一角色 |
| 浏览器地址簿管理员 | 检查浏览器一侧可能保存的 DNS 结果 | 地址簿窗口 | 本地检查顺序只是故事简化，不写成所有实现的固定流程 |
| 系统管理员 | 检查操作系统缓存、本地解析设施和 `hosts` 等信息 | 系统档案、铁皮柜 | 不属于浏览器内部员工 |
| 根域名服务器值班员 | 把查询引向顶级域名服务器 | 圆形根窗口、指路条 | 通常不给最终主机地址 |
| 顶级域名服务器管理员 | 把查询引向目标区域的权威 DNS | 顶级域名窗口、指路条 | 不与权威管理员合并 |
| 权威管理员 | 管理域名区域的正式记录，返回 CNAME、A、AAAA 和 TTL 等信息 | 高档案柜、红色最终记录章 | 可以按不同 DNS 区域出现多位实例 |
| 浏览器海关 | 执行同源策略与 CORS 检查；冷静、刻板、善于反问 | 来源登记表、闸门、印章、检查机 | 负责脚本能否读取跨源响应，不负责 Cookie 是否随请求发送 |
| Cookie 行李检查员 | 按 Domain、Path、Secure、HttpOnly、SameSite 和有效期等规则检查 Cookie | 哨子、名单、闸门和扩音器 | 与浏览器海关是相邻岗位，不是同一个人 |
| 服务器档案员 | 根据 Session 标识查服务器状态，并负责业务身份、权限和 CSRF 防护 | 档案窗口、Session 仓库、毯子 | 不能把安全责任全部推给浏览器 |

## 不可合并的角色边界

以下不是待修复的文字问题，而是技术机制本身不同。后续可以让这些角色发生冲突，但不能把他们合并成一个岗位。

1. **浏览器老大不等于 JavaScript 老大**：前者统筹浏览器，后者负责执行页面 JavaScript。
2. **浏览器侧与服务器侧的同名角色不是同一实例**：首次出场或确实可能混淆时，用所在场景、通话关系或一句动作交代身份即可；后文不必反复写“服务器侧 HTTP”“服务器侧 TCP”这类全称。
3. **浏览器海关不等于 Cookie 行李检查员**：CORS 判断脚本能否读取响应，Cookie 规则判断 Cookie 能否随请求发送。
4. **Promise 不等于微任务**：Promise 是状态与结果的容器；其处理函数满足条件后，才会安排相应微任务。
5. **脚本 `async` 不等于 `async` 函数**：前者骑摩托、控制脚本加载执行；后者拿暂停牌、与 Promise 和 `await` 配合。
6. **QUIC 不等于 UDP**：UDP 目前是通道，没有建立固定人格；QUIC 才是自带可靠性和 Stream 的运输角色。
7. **Web Worker 不等于 Service Worker**：前者主要承接独立线程中的计算，后者有自己的生命周期，可以在作用域内处理 `fetch` 等事件；两者不能因为都叫 Worker 就共用职责。
