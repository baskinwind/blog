## 接下来的主线：页面活起来

前面的文章已经从用户点击一路写到主线程堵塞，再把重计算交给 Web Worker。接下来沿着 Worker 家族往网络路口走：页面不只要在有网时响应，还要面对断网、实时消息和积压。

### [ ] 23.《半路拦车的代理人》——Service Worker 与离线缓存

断网警报响起，URL 的请求车刚要掉头，一名 Service Worker 从路边岗亭冲出来：“服务器不在，我这里还有一份！” 浏览器海关随即追问：谁允许它拦截请求？

核心内容：

- Service Worker 与 Web Worker 的区别
- 注册、安装、激活和接管页面
- 作用域与安全上下文
- `fetch` 事件与请求拦截
- Cache Storage
- cache-first、network-first 等基本策略
- 更新为何不能立即接管旧页面
- 离线能力的边界

核心冲突：旧版 Service Worker 已经下班，新版却被堵在等候室；页面一边催更新，一边又不肯交出控制权。

### [ ] 24.《服务器非要主动开口》——WebSocket

HTTP 每次都要等浏览器先提问，服务器终于拍桌子：“有新消息为什么不能直接告诉页面？” 双方准备打通一条长期双向线路，TCP 老司机却先拿出一摞保活和断线重连表格。

核心内容：

- HTTP 请求响应与实时通信的矛盾
- WebSocket 如何通过握手建立连接
- 全双工通信与消息帧
- 文本帧、二进制帧和关闭帧
- 协议层 Ping/Pong、应用层心跳、断线与重连
- `bufferedAmount`、消息积压与背压限制
- 与轮询、SSE 的适用场景区别

核心冲突：服务器终于能主动发消息，却一口气塞来几千条通知，页面收件室瞬间爆仓。

## 后续候选

以下选题暂不编号。完成“页面活起来”主线后，再根据承接关系决定顺序。

- **《import 带来一整支亲友团》——ES Modules**：模块图、静态导入、模块缓存、`defer` 行为、动态 `import()`、循环依赖与顶层 `await`。
- **《CSS 大厅争夺王位》——层叠与优先级**：来源、重要性、层叠层、选择器优先级、继承和源码顺序；让几条样式围绕同一个颜色争夺最终解释权。
- **《屏幕阅读器看见了另一棵树》——可访问性树**：语义化 HTML、角色、名称、状态、焦点顺序，以及 DOM 如何映射成辅助技术能理解的结构。
- **《陌生脚本闯进执行大厅》——XSS 与 CSP**：恶意脚本如何进入页面，输出编码、CSP、nonce、hash 和 Trusted Types 分别守哪道门。
- **《两个 iframe 隔墙喊话》——页面隔离与 `postMessage`**：同源限制、iframe、`sandbox`、跨窗口通信，以及为什么必须核对 `origin`。
- **《页面里长出一间密室》——Shadow DOM**：宿主、影子树、样式隔离、事件重定向、插槽和自定义元素。
- **《仓库太大，Cookie 装不下了》——IndexedDB**：对象仓库、事务、索引、异步操作、版本升级，以及它与 Web Storage、Cache Storage 的分工。
- **《资源调度员被催疯了》——加载优先级**：预加载、预取、懒加载、`fetchpriority`，以及“提前加载”为什么不等于“越多越快”。
- **《后退按钮打开了冷冻舱》——页面生命周期与 BFCache**：导航、冻结、恢复、`pageshow`、`pagehide`，以及某些页面为什么无法进入往返缓存。

## 选题原则

- 优先选择能承接上一篇结尾的题目，形成连续剧情。
- 一篇只解决一个核心矛盾；相关概念过多时拆成两篇。
- 已经在旧文章里讲清楚的机制只做回顾，不重复铺陈。
- 比喻先让读者看见问题，准确结论随后收住边界。
- 涉及仍在变化的浏览器能力时，动笔前重新核对规范与主流实现。
